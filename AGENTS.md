# Project Instructions

- After making changes, running meaningful checks, recording decisions, or discovering environment constraints in this repository, update `project-log.md` with a dated entry.
- Treat `project-log.md` as the source of truth for prior work in this project.
- Build this project using TDD. For application behavior, write or update unit tests before implementation.
- Maintain full unit test coverage for implemented business/application behavior. Integration or functional tests may be added later or alongside unit tests when they provide useful confidence.
- Do not immediately generate the full project.
- Do not make major technical decisions without confirmation.
- Do not implement core snoring or apnea detection logic automatically.
- Keep the project small at first but expandable.
- Generate boilerplate only after explicit confirmation: "Proceed with scaffold."
- The user is experienced with Java 8 but newer Java features may be unfamiliar. When future code uses modern Java features or idioms newer than Java 8, briefly point out the coding decision and explain why it was used.
